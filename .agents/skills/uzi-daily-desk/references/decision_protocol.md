# 每日事件交易台决策协议

## 时段模式

### 盘前

只做事件地图和预案，不声称已经有盘中买点。输出关注题材、核心候选、预期开盘情形，以及每种情形对应的观察/放弃条件。

### 开盘初段与盘中

使用截止当前已完成的分钟数据。重点验证：题材是否同步、核心是否被替代、抛压是否释放、成交额是否有效放大、价格是否稳定或收回关键价。触发发生在当前 K 线完成后，计划成交在下一根。

### 尾盘

优先判断隔夜事件是否仍成立、尾盘资金是否回流核心、次日是否可能有新增买盘。没有事件持续性或已集体高潮时，不因当日涨幅漂亮而持有隔夜。

### 盘后

保存实际发生的事件、信号、未成交原因和后续验证目标。盘后标签只能用于下一交易日，不得倒填成当天买点。

## 证据层

每条关键事实保存 `source`、`knowledge_time`、`event_time` 和 `asof`。优先级：

1. 交易所/公司公告、政策发布机构等原始来源；
2. 东方财富事件池和行情接口、AKShare/BaoStock 原始行情；
3. 可核验财经媒体；
4. 论坛、股吧和社交热度只能作为注意力代理，不能单独构成题材事实。

网络搜索结果必须与行情截止时间对齐。盘后新闻不能解释为盘中已知信息。

## 动作状态

- `NO_TRADE`：环境、事件、角色或成交任一不合格。
- `WATCH`：事件/角色值得跟踪，但尚未出现可成交触发。
- `PROBE`：此前核心在分歧中先释放抛压，随后出现可观察稳定，允许投入单笔预算的一小部分。
- `ADD`：已有试错仓且题材同伴、成交量和价格重新确认，下一根可成交时才允许增加。
- `HOLD`：持仓角色未被替代，题材和赚钱效应仍成立。
- `REDUCE`：题材扩散减弱、高潮/炸板增加或角色优势下降，但尚未完全证伪。
- `EXIT`：事件被证伪、核心被替代、承接失败，或已到预先声明的退出时点；仍须遵守 T+1 和跌停不可成交。

`PROBE` 与 `ADD` 不是同一时刻。若用户没有提供账户风险预算，使用比例描述，不给出股数。

## 候选输出

每只股票至少输出：

| 字段 | 含义 |
|---|---|
| 代码/名称 | 可核验标的 |
| 当前动作 | 七种状态之一 |
| 事件及知识时间 | 为什么今天进入视野 |
| 题材阶段 | 萌发/确认/高潮/分歧/洗筹/修复/衰退 |
| 个股角色 | 先锋/空间/换手核心/幸存者/跟风 |
| 当前证据 | 行情、量能、同伴和环境 |
| 下一触发 | 未来才允许执行的条件 |
| 放弃/退出 | 条件被破坏时怎么办 |
| 可成交检查 | 下一根、涨跌停、停牌、T+1 |
| 仓位 | 相对单笔风险预算，而非账户绝对推荐 |
| 置信度与缺失 | 数据不足和相反证据 |

在候选表之前先给市场结论；在候选表之后给“今天最可能出错的地方”。没有合格标的时只输出空仓原因和继续观察的事件，不补足数量。

## 每日留档

保存机器可读快照时至少包括：`asof`、市场状态、事件列表、题材阶段、候选角色、动作、触发条件、失效条件、数据来源、知识时间、后续 1/2/5 日可成交收益和是否触发。后续结果字段只能在未来到达后追加，不能覆盖原始判断。
