# 游资心得量化研究

将两册公开心得视为可验证的交易假设，而不是任何个人的私有算法。默认目标是得到“当时能知道、当时能成交、事后能复核”的候选与回测；若用户要求只研究某一位，保持该体系纯净，不混入其他流派。

## 决策顺序

1. 先判断市场环境和赚钱效应：冰点、退潮、震荡、强势或高潮。弱市降仓或空仓，高潮只做确认充分的核心，不因个股漂亮而绕过环境许可。
2. 再判断主线和群体合力：优先有点时可核验的事件原因/概念及扩散、相对强度和量能同步的群体；静态行业只能作为弱代理，不能直接命名为主线。单只上涨、无同伴和无持续性的“伪主线”不算合力。
3. 在主线内做龙头/核心排序：用当时的涨幅、行业内相对强度、历史强势、承接和量能排序，不把事后龙头标签倒填到过去。
4. 只寻找可执行的触发：右侧确认、分歧后的回稳/回封、恐慌后的同步转稳都可以，但必须避开一字锁板、明显追高和失去承接的弱转弱。
5. 预先写出成交与退出：信号截止时刻之后的第一根可成交K线才是入场；下一根锁涨停/跌停不强行成交；预判试错与确认加仓要分成不同仓位和成交时刻。A股现货当日新仓不得当日卖出，最早退出必须符合T+1；弱就走也不能突破这一成交约束。

## 量化时必须保留的约束

- 盘中横截面只能聚合 `datetime <= cutoff` 的数据；日线特征只能使用信号日前完成的交易日。
- 行业/概念只能使用当时已经生效的快照；无法证明生效时间时标注为代理变量并降低结论强度。
- 交易结果字段（入场后收益、是否涨停、未来最高价等）绝不能参与触发、排序、仓位或参数选择。
- 入口价格使用 cutoff 后下一根5分钟K线开盘或更保守的可成交观察点；涨跌停锁死、停牌和缺失下一根时标记未成交。
- 已经封板的事件通常只是进入观察池；除非能证明下一根可成交，不把收盘涨停本身写成买点。分歧低吸必须先定义当时可见的抛压释放/稳定条件，修复确认只能在完成后于下一根成交。
- 同时报告事件收益、非重叠组合收益、动态仓位、固定满仓对照、费用、成交率、最大回撤和样本覆盖。样本不足时不年化。
- 至少做时间切分（开发段/最后样本外段）、市场状态切片、模式切片和少量预先声明的参数扰动；只允许用开发段选型，最后样本外段冻结验收。
- 固定起始股票池要明确幸存者偏差；不要把固定CSI800或最近可用股票池结果写成全市场无偏结论。

## 输出格式

每个候选都说明：当时的市场状态、主线/群体依据、核心排序依据、触发模式、计划成交时点、未成交条件、预期验证信号、失效条件和仓位上限。若没有同时满足环境、主线、核心和成交条件的标的，明确输出“观察/空仓”，不要为了给出股票而放宽规则。

需要完整回测时，把 `long_uzi_state_backtest.py` 仅作为旧行业动量反例基线；日线事件状态使用 `daily_event_role_backtest.py`，盘中可成交验证使用 `event_role_minute_execution.py`。先审计数据覆盖，再运行预声明版本并报告真实样本外结果。该 skill 不承诺收益率、胜率或未来表现。

详细的书中原则到特征的映射见 [references/quant_rules.md](references/quant_rules.md)。
