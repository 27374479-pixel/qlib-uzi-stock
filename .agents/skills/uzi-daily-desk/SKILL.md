# 游资事件交易台

把人物 skill 视为不同研究镜头，由本 skill 统一处理数据时点、冲突、成交和风险。目标是生成可人工验证的条件化决策，不是每天强行荐股，也不声称复原任何人的私有算法。

## 每次调用

1. 记录北京时间、交易日期和所处阶段：盘前、开盘初段、盘中、尾盘或盘后。先检查本地数据的最新知识时间；行情或事件会变化时必须刷新或联网核验。
2. 先建立事件地图：新公告/政策/新闻、首次进入涨停或异动群体、题材扩散、连板/炸板/跌停、封板时间、成交额与换手。来源及知识时间必须随结论保存；无法取得真实题材原因时写“未知”，不得用静态行业冒充。
3. 判断市场许可：赚钱效应、涨停质量、炸板扩散、前强反馈、指数与小盘广度。退潮或无赚钱效应时优先空仓；环境不能被单只强股绕过。
4. 判断题材阶段：萌发、确认、高潮、分歧、洗筹、修复/二波或衰退。高潮不追普通跟风；分歧只研究此前已确认的核心/幸存者。
5. 识别角色：先锋、空间高度、换手核心、分歧幸存者、补涨或跟风。角色必须由当时证据支持，不能把未来涨幅倒填为“龙头”。
6. 再给动作。空仓者只可得到 `NO_TRADE / WATCH / PROBE / ADD`；持仓者才可得到 `HOLD / REDUCE / EXIT`。卖出判断需要用户持仓、成本、可卖数量和买入日期；缺失时输出条件，不假定仓位。
7. 保存本次事件快照、候选、触发与放弃条件，供未来盲测。不要因用户期待机会而降低标准。

详细决策和输出字段见 [references/decision_protocol.md](references/decision_protocol.md)。需要回测或审计代理有效性时，同时读取 `../uzi-book-quant/references/quant_rules.md`。

## 成交硬约束

- 已封死涨停、一字板或下一根无可成交价格：只观察，不能写成买入。
- 盘中条件在当前 K 线完成后才成立，最早按下一根可成交开盘计划。
- A 股现货新仓遵守 T+1；不得给出买入当日卖出的伪止损。
- “预判试错、确认加仓”分开：试错只占用户给定单笔风险预算的一部分；未确认不得按满仓收益描述。
- 不自动发送订单。给出建议时同时给出证据、预期、失效、最大风险和“不交易”条件。

## 人物视角的使用

- 炒股养家：主镜头，检查情绪周期、场外需求与场内筹码、预判试错和确认加仓。
- Asking：检查主线节奏、盘前准备和弱市是否应回避。
- 赵老哥：检查是否真是新题材、是否存在龙头与资金合力。
- 职业炒手：检查顺势、弱市回避和回撤纪律。
- 冷狐冲：仅在涨停确认/打板问题中检查市场氛围与可成交封板，不把其打板逻辑混入低吸触发。

不要简单投票或平均分数。若视角冲突，列出冲突证据；环境否决、题材不明或不可成交任一成立时，结论优先降为 `WATCH` 或 `NO_TRADE`。
